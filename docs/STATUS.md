- **History:** persistence, reopening, per-user isolation and the 365-day expiry already worked; tests now prove it end to end (`tests/test_web_history.py`). The one defect was that every conversation was labelled by its date because no title was ever stored. A title is now **derived on reading** from the first unexpired user message (60 code points, then "…"), by `house_helper/persistence/conversations.py`; nothing is stored, so retention is unchanged and the title goes with its message. The page applies the same rule to a conversation it has just made, and a differential test compares the page's rule with the server's over more than 1000 texts. `list_conversations` now requires `now=`.
- **Favorites:** table `favorite_recipes` (**migration `0007_favorite_recipes`**, the head moves from `0006`): one row per saved answer with the owner, a title, the text, the id of the source message (a plain number, **no foreign key** to the history; unique per user, so saving twice is one favorite), the creation time and **no expiry**. `GET/POST /api/favorites`, `GET/DELETE /api/favorites/{id}` (`house_helper/web/favorites_api.py`, `house_helper/persistence/favorites.py`). The text is copied from the database, never taken from the request; any assistant answer can be saved, not only a detected recipe; at most **100 per user** (`409 favorites_full`); another person's, a missing and a malformed id are all the same `404 favorite_not_found`.
