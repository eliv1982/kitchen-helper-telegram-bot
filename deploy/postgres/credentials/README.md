# PostgreSQL credential directory (HH-DB-01 WP-2B)

This directory is the default host location for the per-role libpq passfiles selected by the
WP-2B OD-8 decision. **No real credential is stored in this repository and no credential is
generated by this work package.** The files below are git-ignored; this README is the only
tracked file here.

| File | Read by | Login | Database field |
|---|---|---|---|
| `hh_app.pgpass` | the web service | `hh_app` | `house_helper` |
| `hh_migrate.pgpass` | the `migrate` one-shot | `hh_migrate` | `house_helper` |
| `hh_provision.pgpass` | the `provision` one-shot | `hh_provision` | `house_helper` |
| `hh_purge.pgpass` | the `purge` one-shot | `hh_purge` | `house_helper` |
| `hh_backup.pgpass` | the `backup` one-shot | `hh_backup` | `house_helper` |
| `hh_restore.pgpass` | the `restore` one-shot | `hh_restore` | `*` (OD-2 is open) |
| `postgres_superuser.password` | the PostgreSQL image's first-init bootstrap only | `postgres` | not a passfile |

Each passfile is one standard libpq line:

```text
hostname:port:database:username:password
house-helper-db:5432:house_helper:hh_app:REPLACE_WITH_THE_ROLE_PASSWORD
```

A password containing `:` or `\` must be escaped with a backslash, as libpq requires.

## Ownership and mode (the deployment host)

The files are bind-mounted read-only into exactly one container each. Compose does not copy
or re-own them, so the host file's owner and mode are what the container sees:

* role passfiles: owner and group `10001:10001` (the application image's uid/gid), mode
  `0600`;
* `postgres_superuser.password`: owner and group `0:0`, mode `0600` (the official image's
  entrypoint reads it as root before dropping privileges).

`deploy/postgres/preflight.py` refuses a file that is missing, is a symlink, is readable by
group or other, or carries another login's line. It never prints a file's contents.

## What does not belong here

* The SQLite deployment's environment file. This directory holds only PostgreSQL credentials.
* The bootstrap superuser password past WP-2C enrollment. Its later lifecycle (rotation or
  retirement) is a WP-2C credential operation under OD-8, not part of WP-2B.
* Any credential for `hh_owner`: that role is `NOLOGIN` and is assumed by `hh_migrate` or
  `hh_restore` with `SET ROLE`.
